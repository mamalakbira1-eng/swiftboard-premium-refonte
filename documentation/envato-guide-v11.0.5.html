SwiftBoard 11.0.5

Envato customer guide — A Reddit-style WordPress forum theme for bbPress.

Package scope. This archive contains the installable theme. WordPress, bbPress, SMTP, OAuth provider accounts, Redis, a CDN and hosting services are not included and must be configured separately.

1. Requirements and installation

ComponentBaseline
WordPress6.4 or later; verify the production version before deployment.
PHP8.0 or later. PHP 8.4 is the primary QA runtime for this release.
bbPressRequired for forums, topics and replies.
HTTPSStrongly recommended, and required for secure OAuth and production authentication.

Install WordPress on staging first. Install and activate bbPress. In Appearance → Themes → Add New → Upload Theme, upload swiftboard-v11.0.5-envato-installable.zip, install it and activate SwiftBoard. Go to Settings → Permalinks and click Save Changes once. Verify that the forum archive, forum, topic, reply, search, profile and login pages load before importing content.

2. bbPress, roles and permissions

Create forums from Forums → New Forum. Verify at least one published forum, topic and reply. The expected role model is visitor, member, author, moderator and administrator. Give moderators only the bbPress moderation capabilities they need. Never grant administrator rights to make a forum feature work.

RoleExpected behavior
VisitorRead public content. Vote mutations must be rejected.
MemberCreate permitted content and use authenticated mutations with a valid REST nonce.
AuthorMember behavior plus the WordPress author capabilities granted by the site owner.
ModeratorModerate bbPress content without administrator access.
AdministratorConfigure the site, import data and manage security settings.

3. Migration V2 and bulk import

Migration V2 preserves stable source identifiers and imported dates. Import topics and replies, build the source-to-WordPress ID map, then apply reply relationships and mentions in a second pass. Rows may be out of order.

source_reply_id,source_topic_id,content,author,reply_to_source_id,date
r-100,t-10,"First reply",alice,r-90,2026-01-04T12:30:00Z

The CSV date is the content publication date; upload time does not replace it. Votes are imported as anonymous aggregate counts. Voter identities are not imported. Topic views use the dedicated SwiftBoard view value and may include an explicit imported bonus. Karma follows the SwiftBoard bonus contract and is not silently converted into an absolute final score.

4. Images

Use HTTPS image URLs and confirm that you have permission to redistribute them. The importer and upload flow must validate MIME type, extension, size and dimensions. Never import executable files as images. Keep a record of image licenses for commercial distribution.

5. Vote security contract

The documented contract is: an unauthenticated visitor receives 401; an authenticated user without the required REST nonce receives 403; an authenticated user with the required capability, valid nonce and valid parameters receives 200. Anonymous aggregate counts may be migrated, but voter identities are not stored by this contract.

6. OAuth and social login

Keep provider secrets outside the theme package. Use HTTPS, a state value bound to the initiating session, provider-subject verification, a strict redirect URI and server-side token validation. Do not place client secrets in JavaScript, CSV files, screenshots or support requests.

7. SMTP, notifications and WP-Cron

Configure SMTP with a maintained WordPress mail solution or your host. On staging, test password reset, account notifications, moderation notices and digest emails using a sink mailbox. Verify WP-Cron or a system cron for digest, notifications, cleanup and cache maintenance. Do not put SMTP credentials in the theme or the developer archive.

8. Cache, CDN and security headers

Do not share-cache private pages or user-specific nonces. Configure cache variation by cookie and purge rules after mutations. Add the following header at the reverse proxy or web server for SwiftBoard static assets:

add_header X-Content-Type-Options "nosniff" always;

Verify JavaScript, CSS, AVIF/WebP and font responses through the real staging domain after CDN purge:

curl --fail --silent --show-error --head \
  https://staging.example.com/wp-content/themes/swiftboard/assets/js/main.js \
  | grep -i '^X-Content-Type-Options: *nosniff$'

9. Privacy, GDPR, uninstall and rollback

Back up database, theme files, uploads and configuration before an upgrade or destructive action. Export and delete a test account on staging. A theme switch must not silently delete SwiftBoard or bbPress data. Use the explicit administrator-confirmed cleanup procedure and retain a restorable backup. Test a complete rollback before production.

10. Troubleshooting

ProblemCheck first
Forum URLs return 404Activate bbPress and save permalinks.
OAuth failsCheck HTTPS, redirect URI, state validation and server time.
Emails are missingCheck SMTP credentials, sender policy, delivery logs and spam quarantine.
Users see private dataTemporarily disable shared cache and check cookies, Vary and purge rules.
Import stopsCheck memory, timeout, upload limits and resume from the last stable source ID.
Dark mode looks wrongClear browser/CDN caches and verify CSS variables and contrast.

11. Support and release information

When contacting support, include SwiftBoard version, WordPress, PHP, bbPress, browser, URL path, reproducible steps and a redacted log. Never send passwords, OAuth secrets, SMTP credentials, cookies or full database exports.

SwiftBoard 11.0.5 includes search output escaping, OAuth and vote hardening, non-destructive theme lifecycle handling, WPCS/PHPUnit QA improvements and bounded DAST tooling. The developer archive contains the engineering reports and CI files; the Envato archive is the installable customer package.
